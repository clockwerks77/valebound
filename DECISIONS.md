# DECISIONS

Every default chosen where DESIGN.md says OPEN, is silent, or disagrees with
itself. DESIGN.md (`docs/DESIGN.md`) stays the single source of truth; change
any line here and I will follow it.

## Build and tooling

| # | Decision | Why |
|---|---|---|
| D-01 | Builds run on GitHub Actions, not in Claude's workspace. Every push is analysed and tested; the APK is built for commits marked `[apk]` or manual runs. | The workspace's network policy blocks pub.dev, Google's SDK hosts and Maven, and no Flutter toolchain was on the PC. Building the APK only on request keeps the download link steady and saves included Actions minutes. |
| D-02 | Flutter pinned to 3.47.x (currently 3.47.9, Dart 3.13.7). | 3.50.0 came out days ago and begins moving Material out of the core SDK. Moving up is a deliberate later step, after a patch release. |
| D-03 | No state-management package: one `ChangeNotifier` controller. | Simplest thing that works for one player on one device; fewer dependencies. |
| D-04 | The Android scaffold is generated by `flutter create` in CI and committed, never hand-written. | Avoids guessing Gradle files. |
| D-05 | Runtime dependencies: `drift`, `drift_flutter`, `path_provider`, `uuid`. None makes network calls at runtime. Fonts (Fraunces, Figtree; SIL OFL 1.1) are bundled rather than fetched. | DESIGN §9.2: no network. A test checks the pubspec and source for network packages and URLs. |
| D-06 | Blender / 3D: not used, not proposed. | DESIGN §13 pipeline. |

## Phase 2: the world, the journey and the vault

| # | Decision | Notes |
|---|---|---|
| D-31 | **Restoration is worked out from the materials gathered.** Twenty drafted places wake in a fixed order, four to a region; each asks for some Timber, Stone and Star Shards. A place wakes the moment everything it asks for has been gathered, with no button to press. Stored totals are "gathered in all" and never go down; what is "in the stores" is gathered minus what has been built. Several places can wake from one quest. | §3A and §5.3 ("counters that feed World Restoration", "no shop, no prices"); §4.1 ("when a restoration threshold is crossed"). Because the map is a pure function of totals that only grow, nothing can un-restore, and materials earned in Phase 1 already count. |
| D-32 | **Regions, places, villagers, costs** are drafted, all original: Hearthmere (village), Larkdown (hills), The Silverrun (river), Highcairn (peaks), Old Lanternhall (ruins). Costs start at 3 materials (The Gate Lantern) and rise to 62 (The Lanternhall); the whole drafted Vale is 520 materials. **The road is 200 Paces**, 40 per region, so there are now **twenty** Discovery scenes, four to a region (eight added to Phase 1's twelve, and the order regrouped by region). | §7 "builder to draft". §7A.4 asks for about twelve scenes; twelve would have ended the road two regions early. A discovery is stored by its key, so one already found still shows as what it was. |
| D-33 | **After the twentieth place**, every further 10 Timber + 10 Stone + 10 Star Shards lights one more lantern along the road. | Keeps "every completed quest restores something" true however long the app is used. |
| D-34 | **A fixed signing key** for personal builds is kept in the private repository (`android/app/personal-debug.p12`; the password is in `build.gradle.kts`). | Without it each CI run signs with a throwaway key and Android refuses to install one build over another, which would wipe the data on every update. The key only identifies sideloaded personal builds; it would need replacing with a private one before any public release. |
| D-35 | **Undo.** A quest you tap done waits five seconds, with an Undo on its card, before anything is awarded. Leaving the app commits it at once. Completions the app makes itself (a timer reaching its target), the Campfire's "Close the day" and "I already did this" in the quest creator commit immediately. | Asked for by Adam. Nothing is ever taken away, so §6.4 holds: within the window nothing has been given yet. |
| D-36 | **Tricks.** Sniff Out and Fetch are once a day, given on the first companion or shared quest after the trick is learned (so learning it mid-day still counts). Fetch carries one of whichever material the current place still needs. Scout shows the next Discovery as a dark marker on the road and a one-line hint. Old Friend adds a scene of the two of you to the Party Sheet and a line at the Campfire. **Comfort** unlocks at L8 but acts on the comeback quest, which is Phase 3. | §7A.3. |
| D-37 | **Companion Gifts are gear.** §7A.3 mentions "Companion Gifts (below)" but never defines them, so a gift is the piece of gear that arrives at each Bond milestone. Four more pieces arrive at companion levels 3, 5, 7 and 9, between the tricks. Eleven pieces in all, named to suit any kind of companion; one can be worn, shown as a badge on the portrait. | Simplest reading. §7A.3 asks for per-kind illustrated variants; those need painted art (ASSETS.md). |
| D-38 | **Hero cosmetics**: five portrait frames and five banner colours by hero level, five village decorations by places restored (drawn on the map). Frames and banners can be chosen in the Inventory. | §5.3 lists the kinds; the items are drafted. Nothing gates a function. |
| D-39 | **The Still**: six drafted creatures (Drowsel, Mistling, Hushmoth, Yawnstone, Dozewisp, Fogfinch). Each Heroic or Boss quest shows one on its card and on the map until it is done; a quest always meets the same creature. | §7. Presentation only. |
| D-40 | **Villagers** greet the Dawn board and say goodnight at the Campfire once their place is restored, one a day in rotation. Before the Gate Lantern is lit nobody is home, so there is no line. | §7: "NPC portrait + one line". |
| D-41 | **Inventory** lives on the Character tab behind a Party / Inventory switch. When the Fold is open it splits like the Party Sheet: the hero's things on one pane, the companion's on the other. | Honours both §8.3 (hero beside companion) and §9.1 (Character + Inventory side by side) without a fifth tab. |
| D-42 | **Settings** opens from the slider icon on the Board header (and at the foot of the rail when open). **Campfire** opens from the Campfire Review card; after the day is closed the card becomes "The campfire is lit" so the note can still be changed that evening. | §9.1 fixes the four destinations, so these are not tabs. |
| D-43 | **Export queue.** A day needs exporting whenever its log has no export stamp; any change to the day clears the stamp. Each export writes `Character Sheet.md`, `Quests.md` and every queued day. A past day is written as it stood at its own evening (level, camp position and discoveries are worked out from the completion log). Days with nothing in them make no file. | §11: "queue silently". The database is the queue, so nothing is forgotten if the folder is away for weeks. |
| D-44 | **Export wording.** `Quests.md` gets its own frontmatter (`type: valebound-quests`, `updated`, `active_quests`). The XP column reads `25 XP`, `10 Companion XP` or `13 XP + 25 Companion XP`. `quests_total` is the number of quests on that day's board. `steps` appears only when a steps figure exists for the day. `## World` is always present. | §11 fixes the fields; these are the details it leaves open. The `type:` values stay as the design gives them even if the app is renamed. |
| D-45 | **Vault settings** (the folder's address) are kept in Android SharedPreferences on the native side, with the persisted folder permission. No Flutter plugin was added for it. | §9.2: SharedPreferences for simple settings. Fewer packages. |
| D-46 | **Backup file**: one JSON document, `format: habit-adventure-backup`, holding every table. Restoring replaces everything on the device, only after the whole file has been read cleanly; a file that is not a backup, or one from a newer version, changes nothing. | §9.2. The format name does not use the app's display name. |
| D-47 | **Health entries** can be stored and exported now (the table and the Markdown `## Health` section are live); the quick-entry form that fills them is Phase 3. | Brief: Health Log is Phase 3; §11's Health section is Phase 2. |

## Flagged for your call (not built)

- **Navigation when open.** When the Fold is open the navigation is a slim left rail rather than a bottom bar, to keep vertical space on a 4:3 screen. §9.1 specifies bottom navigation for the cover screen only.
- **Kind-specific gear art.** §7A.3 asks for gear illustrated per companion kind. That needs painted art; today gear is a name, a line and a badge.
- **Tapping the map.** The map is a picture with a list beneath it. Tapping a place to read about it would be a small addition if you want it.
